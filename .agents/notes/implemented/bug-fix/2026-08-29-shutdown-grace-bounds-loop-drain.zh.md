# Agent Note: Shutdown grace bounds the drain, not only disposal

Status: implemented

[English](2026-08-29-shutdown-grace-bounds-loop-drain.md) | 中文

## 问题

`createProcessShutdown` 会先启动一个五秒计时器，随后释放插件树；成功时它清除该计时器并记录退出码。此后能否退出，取决于事件循环自行排空。释放只归还插件树所拥有的资源，而提供方的 keep-alive TCP 连接并不在其中：当 `dsh --profile headless` 回答了一个未做任何委派的任务后，三条已建立的连接仍占住事件循环，进程再也没有返回给调用方。唯一能防止这一结果的保护，恰恰在释放报告成功的那一刻被解除。

## 决定

宽限计时器在释放成功后继续保持启动状态，因此这五秒同时约束释放**与**其后的排空。若到期时进程仍被占住，它以已经确定的退出码退出。该计时器不计入引用，因此它自身绝不会让事件循环存活；句柄确实排空的运行仍然立即退出。

失败路径与信号路径保持不变：释放被拒绝时，以及传入 `forceAfterDispose` 的入口，仍然立即强制退出；第二次信号仍然完全跳过宽限。

## 备选方案

**找出并关闭那些句柄。** 否决，因为这个集合是开放的，也不归 CLI 枚举——任何插件、提供方或传递依赖都可能打开插件树并不拥有的句柄，只要漏掉一个持有者，挂起就会重现，且表现为无声停滞而非报错。

**释放完成后无条件强制退出。** 否决，因为这会放弃让缓冲输出得以刷新的自然排空，而 `forceAfterDispose` 已经标出了真正需要立即退出的入口。

**让计时器保持被引用。** 否决，因为被引用的计时器自身就会让事件循环存活，从而把每一次干净的快速关机都变成五秒等待。

## 后果

即使插件树之外的东西占住事件循环，一次性运行也会返回给调用方，这正是非交互式监管程序所要求的。代价是：五秒时仍在推进的排空会被切断；而该预算原本就是文档规定的关机上限，现在适用于关机的全过程。`apps/cli/tests/process-shutdown.spec.ts` 固定了这条新路径——释放完成、不强制退出、推进到期限则强制一次——与既有的自然完成用例和信号用例并列。
